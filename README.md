Local Windows launcher and recovery monitor for Roblox accounts.

## Run the standalone .exe (no Python needed)

The packaged build is a single file, `dist\CronusLauncher.exe`, that bundles
Python, PySide6/QtWebEngine, the FastAPI backend, the dashboard and the Lua
helpers. It runs on any Windows 10/11 machine with nothing installed:

```text
1. Copy CronusLauncher.exe to the machine.
2. Double-click it. Done.
```

Runtime data lives under `%LOCALAPPDATA%\Cronus Launcher\`; you can keep the
exe anywhere (Desktop, Downloads, a USB stick).

## Run from source

This repository also runs directly from source. No `.exe` build is required
for development.

### Requirements

- Windows 10 or newer
- Python 3.11 or newer
- Roblox installed

### Install

Open PowerShell in the project folder:

```powershell
git clone https://github.com/your-github-username/Roblox-Auto-Rejoin-windows.git
cd Roblox-Auto-Rejoin-windows
python -m pip install -r requirements.txt
```

### Run

```powershell
.\Run.cmd
```

or:

```powershell
python main.py
```

Cronus starts a local backend on `127.0.0.1` and opens the dashboard window.

## Auto-update

The packaged exe self-updates from this GitHub repository:

1. Every build embeds the upstream commit SHA it was made from
   (`build_info.py`, generated by `ops/build_exe.py`).
2. On startup the app checks GitHub for the current `main` commit and for the
   newest published release (tagged `build-<sha>` by CI).
3. If a newer packaged build exists, the new exe is downloaded next to the
   running exe and applied automatically **when the app exits** - never
   mid-session - then Cronus relaunches itself.
4. The dashboard shows a banner with an "Update & restart" button.

Update control (environment variables):

| Variable | Values | Default |
| --- | --- | --- |
| `CRONUS_UPDATE_MODE` | `auto` / `notify` / `off` | `auto` |
| `CRONUS_UPDATE_REPO` | `owner/repo` | `your-github-username/Roblox-Auto-Rejoin-windows` |

API endpoints: `GET /api/update/status`, `POST /api/update/check`,
`POST /api/update/download`, `POST /api/update/apply`.

> Updating works from source code only in the packaged exe. When running
> `python main.py`, updates are disabled by design (the updater cannot replace
> a running interpreter).

## Building the exe

To produce `dist\CronusLauncher.exe` yourself:

```powershell
python -m pip install -r requirements.txt pyinstaller
python ops/build_exe.py --windowed --name CronusLauncher        # single exe
python ops/build_exe.py --windowed --onedir --zip --name CronusLauncher  # folder + zip
```

The commit SHA is taken from `CRONUS_BUILD_COMMIT` (if set), otherwise `git
rev-parse HEAD`, otherwise the GitHub API default branch. The icon is derived
from `assets/cronus_icon.png`, and a Windows version resource (company,
product, description) is embedded automatically.

## Antivirus false positives

Packaged Python exes are frequently flagged by a small number of antivirus
engines, especially `Bkav Pro` (e.g. `W32.Malware.xxxx`). This is a heuristic
false positive on the PyInstaller "packed + overlay" structure - not a real
detection. In a VirusTotal scan of this project's exe, 67/68 engines including
all major vendors reported the file clean.

What helps:

1. **Use the onedir build** (`--onedir`) - the exe then has no overlay and is
   ~9 MB instead of ~230 MB, which avoids most heuristic flags. Distribute the
   `CronusLauncher-portable.zip`.
2. **Rebuild** - a new binary has a new hash; rescan it on VirusTotal.
3. **Report the false positive** to the engine vendor (on the VirusTotal page,
   click the vendor row -> "Contact vendor", or Bkav's site: bkav.com).
4. **Code-sign the exe** with a certificate - the most reliable long-term fix
   and it also removes the Windows SmartScreen warning.

There is no legitimate malware in this project: it is the Cronus Launcher
source from this repository, packaged with PyInstaller.

## Automatic release builds (CI)

The GitHub Actions workflow `.github/workflows/build-release.yml` rebuilds the
exe and publishes it as a GitHub release (tag `build-<sha>`) on every push to
`main`, so users' apps update automatically. Nothing in this workflow is needed
to run the app - it exists to ship updates.

## Local Data

Runtime data is stored here:

```text
%LOCALAPPDATA%\Cronus Launcher\data
```

Account cookies are stored locally and encrypted with Windows DPAPI.

## Security

- Cookies are encrypted with Windows DPAPI and never committed — see `SECURITY.md`.
- `AccountData.json` and `data/` are ignored by `.gitignore`. Do not paste raw `_|WARNING` cookies in issues/PRs.
- Copy `.env.example` to `.env` for local overrides (`.env` is ignored).

## Clean Generated Files

To remove local cache/build files:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\ops\clean_generated.ps1
```

This removes generated files such as `__pycache__`, `.pytest_cache`, `build`, and `dist`.

## Troubleshooting
